## The big idea

The project builds a small **distributed supercomputer out of three ordinary home PCs** and uses it to solve the **2D heat equation in parallel with MPI**. Then it measures when splitting the work across machines actually helps and when it doesn't.

### The physics problem: heat diffusion on a square plate

Picture a square metal plate where some edges are held hot (for example all four edges, or just the top and bottom). Heat spreads inward over time. The plate is divided into an (N+1)×(N+1) grid. At each time step, every point's new temperature is computed from its four neighbours (the explicit finite-difference method). The parameter `r = α·dt/h²` has to stay small enough, or the simulation becomes unstable and blows up.

A big grid run for many steps means a lot of computation, so it makes sense to split the work across machines.

### The "cluster": three homes joined into one network

- Each of the 3 students runs an **Ubuntu VM** (VirtualBox) on their own Windows PC.
- The PCs are in **different homes**, so they can't see each other directly. **Tailscale** (a VPN) puts them on one private network.
- **SSH** with keys lets one machine (the coordinator) start programs on the others.
- **MPI** (Open MPI) runs copies of the same C++ program as separate processes called *ranks*, and lets them send data to each other.

### How the parallel solver works (the planned final goal)

The grid is cut into pieces and each rank owns one piece:
1. **Strips (1D):** horizontal bands. Each rank swaps one boundary row (a "halo") with the rank above it and the rank below it at every step.
2. **Blocks (2D):** a grid of tiles. Each rank exchanges edges with up to 4 neighbours. Pieces are smaller, but there are more messages.

The parallel output has to match the serial version **bit for bit**. Looking similar isn't enough.

### The key lesson: communication is expensive

This is the central point of the project. The **Part 0** results in your repo show it very clearly:

| | Latency (time for a tiny message) | Bandwidth |
|---|---|---|
| Two processes **in the same VM** | ~0.3 **µs** | ~3,400–5,800 MiB/s |
| Two VMs **over the Internet** | ~18–78 **ms** | ~0.07–0.14 MiB/s |

The Internet link is roughly **100,000× slower** to start a message and roughly **40,000× slower** to transfer data. One 16 MiB round trip between two homes took about **3.7 minutes**. So adding machines can make the solver **slower**, because the time spent exchanging halos can exceed the computation saved. The assignment wants you to measure this, model it as `time ≈ latency + bytes/bandwidth`, and explain it.
